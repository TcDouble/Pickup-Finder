## 2. Project Description

Pickup-Finder is a web application intended to help users discover and participate in pickup events. The application is planned to include user accounts, event information, and map integration to help users find relevant activities and locations. Users will be able to register, log in, and interact with the application through its interface.

The project is planned to include a database for user and event information, a server that connects the user interface to the database, and secure password storage. Additional planned features include real-time updates, profile and event image storage, notifications, and server-side logic for managing events. The final implementation will depend on the team's agreed scope and project requirements.

## 3. Target Audience and Problem

The intended audience is people who want to find or organize pickup activities and connect with others who share their interests. The application aims to make it easier to discover events and access relevant event information in one place.

The interface should be understandable and easy to navigate. Information should be presented clearly, and the design should consider accessibility, including readable text, clear navigation, and usable forms.

## 4. Vision Statement

Pickup-Finder aims to make discovering and joining pickup activities easier by bringing event information, location discovery, and user interaction together in one accessible web application.

## 9. Planned Features and Use Cases

The planned application requirements include:

1. Register a new user account.
2. Log in and log out.
3. View the home page.
4. Store user information securely.
5. Create and view event information.
6. Find events using map integration.
7. Receive real-time event updates.
8. Upload profile and event images.
9. Receive notifications.
10. Enforce event rules and remove past events.

These features are planned requirements; the final feature set will be confirmed by the team.

## 11. Risks and Mitigation (Extra Credit)

The following are potential project risks. The team should review and confirm these risks and their severity.

| Risk | Severity | Mitigation |
|---|---|---|
| Team members have conflicting schedules | Medium | Set meeting times in advance and record decisions and action items. |
| Database or server integration problems | High | Integrate features incrementally and test database connections early. |
| Authentication or user-data security issues | High | Hash passwords, protect sessions, validate inputs, and restrict access to private user data. |
| Map integration takes longer than expected | Medium | Test the selected map solution early and prioritize core event functionality first. |
| Real-time updates or notifications are difficult to implement | Medium | Prototype the feature early and establish a fallback plan if necessary. |
| Team members make conflicting code changes | Medium | Use Git carefully, communicate before major changes, and resolve merge conflicts promptly. |
